# LP で言ってよいこと／いけないこと

BLESC のランディングページ（このリポジトリ）が主張してよい範囲の基準です。

## なぜこの文書があるか

`jbjgjf/BLESC` の `sentra/docs/` で「ページを実装に合わせる」と決定し対応した
項目が、**LP をこのリポジトリに作り直した際に元へ戻りました**（#12 #13 #14）。
決定は BLESC 側の docs に、LP はこちらにあり、両者を突き合わせる仕組みが
なかったためです。

`#12` の教員画面リスクバンドは、`lp_claim_alignment.md` の進捗表で「done」と
記録されたまま、実際には復活していました。**決定記録が実態と食い違っていた**
という点で、これは個別の表現ミスではなく記録の信頼性の問題です。

そこでこの文書を主張の基準としてリポジトリ内に置き、
`npm run check:claims`（CI で実行）が機械的に検査します。

## 出典

基準そのものは以下の 3 点にあります。この文書は**コピーではなくリンクと要約**
で持ちます。食い違ったときは、常に出典側が正です。

| 出典 | 何を定めているか |
| :--- | :--- |
| [`sentra/docs/product_policy.md`](https://github.com/jbjgjf/BLESC/blob/main/sentra/docs/product_policy.md) | 非医療スコープと Language Standard。疾患の断定を禁止し、"may" / "could" / 「考えられる」系の表現を求める |
| [`sentra/docs/educator_display_policy.md`](https://github.com/jbjgjf/BLESC/blob/main/sentra/docs/educator_display_policy.md) | 教員画面に判定を描画しない（2026-08-06 決定）。観測・時刻・根拠のみを出す |
| [`sentra/docs/lp_claim_alignment.md`](https://github.com/jbjgjf/BLESC/blob/main/sentra/docs/lp_claim_alignment.md) | 個別の主張①〜④ごとの決定と期限 |

## 1. 疾患名を目的語に取る「検知」「判定」「診断」「解析」

**禁止。** `product_policy.md` が明示的に禁じています。

> BLESC must not claim to detect depression, suicide risk, anxiety disorders,
> PTSD, ADHD, eating disorders, substance-use disorders, or any other medical
> or mental health condition with clinical certainty.

実装がしているのは、書字ダイナミクス（入力のためらい、書き直し）の計測と、
記述からの観測抽出・グラフ化・ベースラインからの逸脱の可視化です。
「捉える」「可視化する」は事実、「検知する」「リスクを判定する」は実装にも
社内ポリシーにも存在しません。

| ❌ 書いてはいけない | ✅ 書いてよい |
| :--- | :--- |
| いじめ・不登校・抑うつなど心理的リスクの早期サインを**検知**する | 言葉づかいや書きぶりの変化を**捉えて可視化**する |
| 臨床オントロジー知識グラフにもとづく心理的リスク**解析** | オントロジー知識グラフによる記述の**整理** |
| 微細なシグナルを積み重ねて**検知**します | 微細なシグナルを積み重ねて**捉え**ます |
| 一日の落ち込みと続いている不調とを**区別できます** | **見分ける手がかりになります**（判断は教員が行う） |

**否定形は問題ありません。** 「心理的リスクの判定は行いません」「診断は行いま
せん」は、むしろ書くべき表現です。検査もこれを誤検出しません。

疾患名そのものは禁止語ではありません。オントロジーの因果連鎖
「睡眠不足 → 認知機能の低下 → 抑うつ傾向」は、構成概念の名前として出せます。
問題になるのは、それを **検知・判定・診断・解析の目的語に置いたとき**です。

## 2. リスクバンド（高 / 中 / 低）とスコア

**禁止。** `educator_display_policy.md`（2026-08-06 決定）。

理由は検証待ちではなく算術です。有病率 5%・感度 80%／特異度 90% なら陽性的中率
は約 30%、つまり「高」と表示された生徒の 7 割が非該当になります。モデルを改善し
てもこの構造は変わらないため、バンドは検証を待たずに削除されました。

`state_band` / `latest_score` は計算・保存されますが、**描画にも、タイルの
集計にも、並び替えにも使いません**。並び替えに使うと、判定が UI に戻ります。

| ❌ 書いてはいけない | ✅ 書いてよい |
| :--- | :--- |
| リスクレベル / リスク判定 / リスクスコア / 高リスク | 観測 / 観測された記述 |
| 今月のリスクレポート | 要確認の観測 |
| 生徒ごとの「高 / 中 / 低」表示、スコア幅を表すバー | 観測カテゴリ・時刻・入力元・根拠 |
| 重大度順の並び替え、件数タイル | 新しい順（並び順を明示する） |

教員向けモックには次の 3 点が必要です。

1. 根拠と時刻を伴う観測のみ。根拠のない観測は**表示しない**
2. 並び順が判定相当の値になっていないこと（時刻順にし、そう明示する）
3. 診断を行わない旨の記載

## 3. 外部機関名

**許諾が書面で確認できるものだけ。** 許諾済みリストは検査スクリプト
`scripts/check-claims.mjs` の `PERMITTED_ORGS` にあります。**現在は空です。**

学校・教育委員会・投資家向けの B2B で、後から訂正が必要になった場合の損害が
最も大きい種類の記述です。大学側から見れば名称の無断使用にあたりえます。

| 機関 | 状態（2026-09-10 時点） |
| :--- | :--- |
| 京都大学 | **記載不可** — 交渉中・口頭のみ。`lp_claim_alignment.md` の Collaborator 欄は未記入 |
| 株式会社Hatapro | **記載不可** — 社名掲載の許諾なし |

許諾が取れたら `PERMITTED_ORGS` に追加し、あわせて**協働の範囲**を書きます。
「協働によって開発しています」は範囲が無限定で、監修・共同研究・助言のいずれ
とも読めるため、それ単体では不可です。何を共同で行い、何を行っていないかが
読んで分かる粒度にしてください。

## 4. オントロジーの規模に見合った表現

`lp_claim_alignment.md` の①③。現在あるのは `app/ontology/seed/` の
3 サブグラフ（睡眠 / 社会的ひきこもり / 学業上の負荷）、40 ノード・50 エッジで、
それぞれ `ontology/sources.py` の出典 ID（WHO adolescent MH、NICE NG134、
WHO mhGAP、文科省 生徒指導提要）に紐づいています。出典を示せないエッジは
`expert_judgement` と明記されています。

| ❌ 書いてはいけない | ✅ 書いてよい |
| :--- | :--- |
| 臨床心理士の思考プロセスを機械可読な形で再現する | 公開されている医学的ガイドラインをもとに構造化した |
| 医学的研究にもとづき（協働の裏づけなしに） | WHO や NICE など公開文献をもとに社内でキュレーション |

**期限: 2026-09-30。** ①③ が完了しなければ 10-01 に自動的に option A へ
転換します。転換は追加の意思決定を要しません。

## 検査

```
npm run check:claims
```

CI（`.github/workflows/claims.yml`）が PR ごとに実行します。検査対象は
`src/**` の `.ts` / `.tsx` で、コメント内は対象外です（画面に出ないため）。

誤検出は許容する設計です。正しい表現が引っかかった場合は、同じ行か直前の行に
`claims-allow` を含むコメントを置くと抑止できます。**理由も併記してください。**

```tsx
{/* claims-allow: 出典の原文引用であり、Blesc の主張ではない */}
```

抑止を足すときは、この文書に追記すべき例外なのかを先に考えてください。
`claims-allow` が増えていくなら、基準のほうが実態と合っていない可能性があります。
